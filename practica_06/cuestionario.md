# Cuestionario — Guía 06 MVC

1. **¿Qué es un patrón arquitectónico?** Es una solución reutilizable para organizar los componentes y sus relaciones en un sistema.
2. **Ejemplos:** MVC, arquitectura en capas, cliente-servidor, microservicios y arquitectura orientada a eventos.
3. **Patrón frente a arquitectura:** el patrón es una solución general; la arquitectura concreta define la estructura de un sistema determinado.
4. **Criterios de selección:** requisitos, seguridad, mantenibilidad, escalabilidad, rendimiento, equipo y recursos.
5. **Interacción MVC:** la Vista muestra datos y captura acciones; el Controlador las coordina; el Modelo administra datos y reglas de negocio.
6. **Ventajas:** separación de responsabilidades, pruebas, mantenimiento, reutilización y colaboración.
7. **Cuándo no conviene:** aplicaciones mínimas para las que separar capas añade complejidad innecesaria.
8. **Escritorio:** con Swing o JavaFX; componentes visuales en la Vista y manejo de eventos desde el Controlador.
9. **Alternativas:** MVP y MVVM. MVP emplea un Presentador; MVVM facilita el enlace de estado entre la Vista y el ViewModel.
10. **Combinaciones:** MVC para arquitectura; Factory para crear objetos; Strategy para intercambiar algoritmos; Observer para reaccionar a cambios.
11. **Herramientas:** Spring MVC y Spring Boot para servicios web; JavaFX y Swing para interfaces de escritorio; JUnit para pruebas.
